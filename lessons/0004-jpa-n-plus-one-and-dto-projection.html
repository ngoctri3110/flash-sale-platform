Bài 0004 — JPA N+1, fetch plan và DTO projection

Mission: giữ list API nhanh và dự đoán được khi dữ liệu tăng.

Previous · Course map · Glossary · Fetch reference

Ví dụ rất nhỏ

Giả sử load 4 Order bằng một query. Mỗi Order có product là LAZY (chỉ tải khi code thật sự đụng đến nó). Vòng lặp gọi order.getProduct().getName(). Hibernate phát thêm tối đa bốn query Product. Tổng là 1 + N: đó là N+1 query problem.

Không phải mọi LAZY đều xấu. LAZY là default an toàn vì không tự tải graph lớn. N+1 xuất hiện khi một list load entity rồi mapper/view loop chạm association từng row.

Đừng sửa bằng EAGER

EAGER nghĩa là association luôn phải được tải. Nó không nói Hibernate phải dùng một join tối ưu; nó có thể dời hidden query sang nơi khác, làm detail/list không dự đoán được. Senior chọn fetch plan theo use case, không theo mapping global.

Bốn lựa chọn

CáchÝ nghĩa dễ hiểuKhi dùng
Fetch joinViết rõ join trong queryDetail screen với graph to-one/bounded
EntityGraphKhai báo association cần load, không làm query text dàiRepository cần một fetch plan có tên rõ
Batch fetchingGom nhiều lazy association vào vài queryLegacy/entity graph, nhất là to-one
DTO projectionSelect đúng cột response cầnList API production

Fetch join và EntityGraph với to-many collection + offset pagination có thể tạo nhiều row lặp (Cartesian multiplication), page sai hoặc Hibernate phải xử lý in-memory. DTO projection tránh entity graph đó và chỉ lấy response fields.

Project đã chọn gì?

Product list gọi ProductJpaRepository#findProductList, trả ProductListProjection. Order list dùng JdbcOrderQuery select snapshot trực tiếp. Đây là read model; không dùng nó để update aggregate.

Evidence, không đoán SQL

NPlusOneQueryLabIntegrationTest dùng Hibernate Statistics để đếm prepared statement: lazy loop > 2; fetch join/EntityGraph = 1; batch ≤ 2; DTO projection = 1. Product page production có budget ≤ 2 vì một page hợp lệ gồm content query và count query.

Câu trả lời phỏng vấn mẫu

“Bạn xử lý N+1 thế nào?” — “Tôi bắt đầu từ access pattern và đo statement count. List API ưu tiên DTO projection để chọn đúng fields và tương thích pagination. Detail graph nhỏ có thể dùng fetch join hoặc EntityGraph. Batch fetch là fallback để giảm lazy loads. Tôi không bật EAGER global vì nó tạo hidden data access. Tôi có integration regression test với query-count budget, không assert exact SQL.”

Gợi ý

Count query; batch có kích thước hữu hạn; join làm mỗi parent lặp theo child nên database rows không còn tương ứng page of parent.
